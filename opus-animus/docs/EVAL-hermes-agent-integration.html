1. Hermes Agent là gì (cập nhật 2026-06)

Hermes Agent là agent runtime mã nguồn mở (MIT) của Nous Research, ra mắt 25/02/2026, vượt 140.000 GitHub stars trong chưa đầy 3 tháng và hiện là agent được dùng nhiều nhất trên OpenRouter. Điểm khác biệt cốt lõi: learning loop tích hợp sẵn trong runtime — hoàn thành task phức tạp → tự sinh skill document → lần sau gặp task tương tự thì nạp skill đó làm context.

Skills

File SKILL.md (YAML frontmatter + markdown body) theo chuẩn mở agentskills.io — không phải Python class. Lưu tại ~/.hermes/skills/. Agent tự sinh và tự cải thiện skill khi dùng. Cron job có thể nạp skill trước khi chạy prompt.

Procedural memory

Gateway đa nền tảng

Một gateway process route message từ 23 nền tảng: CLI/TUI, Telegram, Discord, Slack, WhatsApp, Signal, Email, Teams… kèm desktop app (từ v2026.6.5) và web dashboard admin.

Telegram sẵn dùng

Memory

3 lớp: agent-curated memory (tự nudge để persist), user modeling (Honcho dialectic), full-text search hội thoại cũ (FTS5 — từ v2026.5.28 không tốn LLM call).

Cross-session

Runtime

Python 3.11+, pip install hermes-agent, Windows native installer (tự lo Python/Node/ripgrep, không cần admin). Execution backend: local, Docker, SSH, Modal, Daytona. Built-in cron scheduler deliver kết quả tới bất kỳ platform nào. MCP client + có thể tự expose làm MCP server. Model tùy chọn: Anthropic, OpenRouter (200+), NVIDIA NIM, OpenAI, custom endpoint — đổi bằng /model.

Python 3.11 — khớp stack
Lưu ý maturity: tốc độ release rất nhanh (v2026.5.16 → 5.28 → 5.29 → 6.5 trong 3 tuần), Windows support mới ở mức beta từ v2026.5.16 (~1 tháng tuổi). API/behavior có thể đổi giữa các bản — phải pin version khi triển khai.

2. Khớp vào kiến trúc Opus Animus

Thiết kế Module C (wiki 2026-04-26-module-c-architecture.md) đã dành sẵn chỗ cho Hermes ở Tầng 3 — Interface. Đánh giá này xác nhận thiết kế đó vẫn đúng, với một hiệu chỉnh quan trọng: điểm tích hợp là CLI contract, không phải Python API. Hermes skill chỉ là file markdown hướng dẫn agent chạy lệnh python run_wiki.py query "..." qua terminal tool — các CLI hiện có (run_wiki.py, run_collect.py, run_daily.py, run_weekly.py) chính là API mà Hermes tiêu thụ, không cần sửa dòng code nào trong pipeline.

Hệ quả với code sẵn có: skills/wiki_skill.py + intent_classifier.py được viết theo contract Python tưởng định (as_hermes_skill() dict) — contract này không tồn tại trong Hermes thật. Hai file vẫn dùng được ở chế độ standalone, nhưng phần intent classification trở nên thừa: Hermes core đã làm natural-language → intent tốt hơn. Không xóa, chỉ không mở rộng.

3. Đánh giá hiệu quả — Hermes thêm gì, không thêm gì

Thêm thật (giá trị mới)
  • Hồi sinh kênh chat không tốn công maintain: Telegram bot tự viết đã disable toàn hệ thống; Hermes gateway cho lại Telegram/Discord miễn phí công bảo trì — "lưu bài này", "tuần này có gì về FDE?" từ điện thoại.
  • Context hội thoại: "thêm tag vào bài vừa lưu" hiểu được — điều CLI stateless không làm nổi. Đây đúng là gap §5.3 trong thiết kế Module C.
  • Cross-module orchestration: một câu hỏi kéo cả wiki query + daily brief + collect log — hiện phải chạy tay 3 lệnh.
  • Built-in cron: về dài hạn có thể thay các entry Task Scheduler kèm delivery kết quả vào chat (Task Scheduler hiện chỉ ghi log, không báo).
  • Learning loop: quy trình thao tác lặp lại (audit-research rồi ingest, weekly review) tự đọng thành skill.
Không thêm (đừng kỳ vọng)
  • Không thêm core functionality: ingest/query/lint/collect/synthesis đã chạy. Hermes chỉ đổi UX — đúng nhận định cũ trong thiết kế Module C §7.
  • Không thay knowledge brain: memory của Hermes là về user/thao tác, không thay được wiki concept-first có cross-ref + traceability.
  • Không thay Opus Home dashboard: review UI dạng visual (Intel, FDE tab) vẫn là dashboard.
  • Không giảm chi phí LLM: ngược lại thêm một consumer LLM mới chạy thường trực (xem §4).

5. Rủi ro & biện pháp

Rủi ro nghiêm trọng nhất với Opus Animus — skill poisoning: Consilium ingest nội dung web không tin cậy (RSS) mỗi ngày. Nếu Hermes đọc các nội dung đó và một lần bị prompt injection trong phiên có sinh skill, chỉ thị độc tồn tại vĩnh viễn trên đĩa dưới dạng SKILL.md và được nạp như trusted context ở các phiên sau. Đây là điểm giao trực tiếp giữa thiết kế self-improving của Hermes và pipeline collect của ta.

6. Plan thực hiện

Theo dev-approach: integration mới → full SDD (RD → SD → BD → build). Tổng effort ước tính 6–9 ngày làm việc rải trong ~4 tuần (có gate chờ ổn định giữa các phase). Mỗi phase có điều kiện dừng/rollback rõ.

  • Phase 0 — PoC cô lập (0.5–1 ngày)

    Cài Hermes trên Windows (pin version, ví dụ v2026.6.5), config baseline an toàn: approval mode, tắt auto-skill, HERMES_WRITE_SAFE_ROOT vào folder sandbox, API_SERVER_KEY, loopback only. Chọn LLM provider tạm (OpenRouter hoặc NIM free tier). Viết tay 1 skill opus-wiki-query/SKILL.md chỉ cho phép chạy python run_wiki.py query.
    Verify: hỏi 5 câu qua TUI, so kết quả với chạy CLI trực tiếp — phải tương đương. Gate: fail hoặc Windows bug chặn đường → dừng, ghi lesson, cost = 1 ngày.

  • Phase 1 — RD + SD (1 ngày, cần approve)

    Viết docs/RD-hermes-skill-layer.md (usage-first: 5–7 câu lệnh NL thực tế user sẽ nói) + SD-hermes-integration.md (ranh giới §2, security baseline §5 thành contract, danh mục skill đợt 1, quyết định LLM provider chính thức từ Open question #1). Cập nhật SA-system-architecture.md Phase 6. Gate: user approve RD trước khi build.

  • Phase 2 — Skill đợt 1: read-only (2–3 ngày)

    BD rồi build 3 skill viết tay, version trong repo tại opus-consilium/skills/hermes/, copy sang ~/.hermes/skills/ bằng script: opus-wiki (query + trạng thái audit queue), opus-brief (đọc daily/weekly logs, trả lời "tuần này có gì"), opus-status (collect log, task scheduler health). Tất cả read-only — chưa có skill nào ghi.
    Verify: dùng thật qua TUI ≥ 1 tuần; đo: số lần dùng/tuần, tỷ lệ trả lời đúng, có lần nào Hermes vượt quyền không (check approval log + diff skills folder hằng tuần).

  • Phase 3 — Gateway + thao tác ghi có gate (2–3 ngày, sau khi Phase 2 ổn ≥ 2 tuần)

    Bật Telegram gateway (đảo quyết định "Telegram disabled" — cần user xác nhận, Open question #2). Thêm skill opus-ingest: Hermes được chạy run_wiki.py ingest --dry-run rồi hỏi xác nhận trước khi ingest thật — giữ nguyên audit gate. Thí điểm 1 cron job Hermes (ví dụ nhắc weekly review + deliver vào Telegram) song song Task Scheduler, chưa thay thế.

  • Phase 4 — Đánh giá & quyết định mở rộng (0.5 ngày, sau 1 tháng)

    Review số liệu Phase 2–3: nếu dùng < 3 lần/tuần → giữ mức hiện tại hoặc gỡ (rollback = xóa ~/.hermes/ + tắt gateway, pipeline không bị ảnh hưởng vì zero code change). Nếu dùng thật → cân nhắc đợt 2: bật lại auto-skill có review gate, migrate dần cron, expose wiki query làm MCP server cho tool khác. Cập nhật BACKLOG/TODO.

Việc KHÔNG làm (chống scope creep)

  • Không dùng hermes-agent-self-evolution (DSPy+GEPA) ở giai đoạn này.
  • Không cho Hermes quyền ghi personal-wiki/, raw/, hay sửa code repo.
  • Không migrate toàn bộ Task Scheduler sang Hermes cron trước Phase 4.
  • Không viết thêm Python wrapper mới — wiki_skill.py giữ nguyên, không mở rộng.
