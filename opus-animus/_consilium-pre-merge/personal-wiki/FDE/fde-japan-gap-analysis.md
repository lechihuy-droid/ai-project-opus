# FDE Japan Gap Analysis

## Summary
This page compares the traditional Japan SIer model with the FDE model. The goal is to identify which gaps matter for real adoption, not to copy Palantir mechanically.

## Key Points
- Pricing must move from man-month logic toward outcome accountability.
- Engineer profile must move from spec follower to embedded problem solver.
- Customer position must move from subcontractor to strategic partner.
- Knowledge capture must move from disposable project docs to reusable ontology and playbooks.
- Sales motion must move from long RFP cycles to bootcamp-style proof with real data.
- Risk must become explicit through pilot scope, KPI design, and risk-sharing terms.
- Tech leverage requires platform and automation, not only better human consulting.

## Why It Matters
The FDE opportunity in Japan is mostly a business-model transition problem. Without changing incentives, customer access, and knowledge capture, AI delivery stays trapped in low-margin SI work.

## Details
Dashboard gap dimensions to preserve:

| Dimension | Current SIer Model | FDE Model | Required Action |
|---|---|---|---|
| Pricing | Man-month | Outcome-based | Build pilot contract templates with KPI and risk model |
| Engineer Profile | Spec follower | Embedded problem solver | Retrain senior engineers into FDE-grade operators |
| Customer Position | Subcontractor | Strategic partner | Reach CTO/COO/business owner, not only prime contractor |
| Knowledge Capture | Project docs | Ontology + AI FDE | Build reusable domain ontology |
| Sales Motion | RFP/SOW cycle | Bootcamp to embed | Design bootcamp methodology for one vertical |
| Risk Profile | Low risk, low upside | Medium risk, high upside | Define risk-sharing and scope control |
| Tech Leverage | Per-project | Platform + ontology | Build internal Foundry-lite patterns |
