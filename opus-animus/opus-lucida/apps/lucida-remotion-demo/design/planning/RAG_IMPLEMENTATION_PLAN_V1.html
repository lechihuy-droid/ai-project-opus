1. Goal và Definition of Done

Goal: cho phép Lucida tìm và xếp hạng component/template/style/motion cùng approved reference evidence bằng hard filters + FTS5, trả provenance và lý do chọn/loại, trong khi renderer vẫn hoàn toàn độc lập với database.

Done khi:

  1. glitch-text là canonical package, có adapter riêng và được runtime resolve từ generated index.
  2. SQLite projection có thể xóa và rebuild deterministic từ canonical packages.
  3. Repository, web, image và theme reference chỉ được index từ approved reference package.
  4. JSON/SQLite query parity đạt 100% trên gold fixtures.
  5. Retrieval benchmark đạt toàn bộ threshold tại mục 10.
  6. Renderer vẫn bundle/render khi file SQLite không tồn tại.

5. Identity, chunk và normalization contracts

5.1 Stable identity

logical entity id   = <entity-type>:<canonical-id>
entity version id   = <logical-id>@<semver>
snapshot id         = snapshot:<source-id>:<sha256[0:16]>
document id         = doc:<snapshot-hash16>:<source-ref-hash16>
chunk id            = chunk:<document-hash16>:<ordinal-4>:<content-hash12>

Database integer rowid chỉ là implementation detail. Mọi relation, artifact và query output dùng stable text ID.

5.2 Chunking v0.1

  • Canonical entity/package: một retrieval document/entity; fields quan trọng được materialize vào search text.
  • Markdown/provenance: split theo heading, sau đó paragraph; target 400–1.200 ký tự.
  • Collector records/code/CSS token: một normalized record là một chunk; hard cap 1.600 ký tự.
  • Không overlap trong v0.1; chunkerVersion=structural-v1.
  • Chunk vượt hard cap được split tại newline gần nhất; không cắt giữa Unicode grapheme.

5.3 Vietnamese search normalization

raw_text       = Unicode NFC, giữ nguyên để hiển thị
search_text    = lowercase(NFC(raw_text))
search_folded  = NFD → bỏ combining marks → đ/Đ thành d →
                 punctuation thành space → collapse whitespace

FTS index cả search_text và search_folded bằng unicode61 remove_diacritics 2. Query có dấu và không dấu phải tạo cùng hard-filtered candidate set trong gold test.

11. Migration, rollback và failure policy

  • Mỗi migration và mỗi projection build chạy trong transaction; lỗi phải rollback toàn bộ.
  • Build vào temporary DB/index, chạy integrity + parity, rồi atomic rename thành last-good projection.
  • SQLite là derived data: rollback operational mặc định là xóa DB lỗi và rebuild từ canonical packages.
  • Generated JSON chỉ được publish sau validation; compiler giữ last-good manifest cho tới khi build mới pass.
  • Không viết migration down cho dữ liệu derived. Rollback schema bằng code version trước + clean rebuild.
  • Nếu Wave 3–6 fail, runtime tiếp tục dùng generated JSON của Wave 2; không block renderer vì DB.

12. Phase gates

Gate A — mở SQLite: canonical glitch-text; provenance; schema validation; adapter riêng; generated index; deterministic preview; runtime không còn mapping thủ công. Phải đạt 7/7.
Gate B — mở reference ingestion: SQLite clean rebuild, idempotency, FK/FTS integrity và JSON parity đều pass.
Gate C — cân nhắc vector: chỉ khi corpus/gold set tăng và FTS5 không đạt Recall@5 hoặc nDCG@5 trong ít nhất hai benchmark liên tiếp sau khi metadata/chunking đã được sửa.
