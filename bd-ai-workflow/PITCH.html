02 / 06 · SOLUTION

Giải pháp tổng thể

Deterministic pipeline + LLM có ràng buộc + 6 human gates

📊 RD.xlsx → ⚙️ Extract + Normalize → ✨ L1 · LLM
JP wording → ⚙️ Patch plan
+ locking → 🛂 Human Approve → ⚙️ Apply + Verify → ✨ L2 · LLM
DD notes → 📦 BD.xlsx + DD.md

1. MCP layer đọc/ghi Excel

Python deterministic (openpyxl/xlwings). LLM không chạm cell trực tiếp. Format preserved binary-diff.

2. LLM chỉ tại 2 call sites (L1, L2)

Section mapping + JP wording (C.6a) + DD notes (E.14a). Verbatim constraint cho số/ID/date.

3. Optimistic locking + approval

Mỗi patch có expected_old_value. Re-run không wipe khách edits. Human approve G2 trước write.

4. Bidirectional traceability + audit

Cell comment [RD-TRACE]. Idempotency check + LLM prompt hash + model_id trong audit log.

03 / 06 · LLM CONTRACTS

LLM call sites & JSON contracts

LLM chỉ chạy 2 lần — mỗi lần có schema, có ràng buộc, có hợp đồng với MCP

CallPhaseMục đíchModelOutput schema
L1 C.6a Section mapping + JP business wording cho mỗi requirement Opus 4.7 BDPatchCandidate
L2 E.14a DD design notes + API/data candidates + open questions Opus 4.7 DDFunctionNotes

Ví dụ L1 — Patch dùng cả LLM output và MCP compute:

✨ Field do LLM produce ⚙️ Field do MCP compute
{ "patch_id": "P-0042", "sheet": "機能一覧", // từ bd_mapping.yaml "cell": "C15", // start_row + offset "expected_old_value": "", // đọc template hiện tại "expected_old_hash": "sha256:e3b0c4...", "new_value": "ユーザー認証", // LLM fields.function_name "source_requirement_id": "REQ-FUNC-001", // LLM + MCP cross-check "source_cell": "RD.xlsx#機能要件!B12", // từ rd_normalized.json "verbatim_tokens": ["3回連続失敗", "アカウントロック"], "llm_trace_id": "L1-REQ-FUNC-001", "conflict_policy": "abort" }
Critical: LLM không quyết định cell address, expected_old_value, patch_id, source_cell — tất cả MCP compute. LLM chỉ produce content + verbatim_tokens để post-validator regex check.

💾 Prompt caching strategy

Layer 1 — System prompt

Role + verbatim rules + JP style guide + output schema spec
~3000 tokens · TTL 1h · hit rate ~95%

Layer 2 — Per-workbook context

rd_normalized.json + mapping YAML + JP examples
~5000 tokens · TTL session · hit rate ~80%

Per-call (uncached)

Single requirement payload
~200–500 tokens

Cost saving ~70–80% so với gửi full context mỗi call. 100+ requirements/workbook vẫn trong ngân sách.
