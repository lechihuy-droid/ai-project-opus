InsightHub Agent — Kiến trúc hệ thống (MVP)

AI co-pilot sinh báo cáo tuần truy vết được cho Front PM. Pipeline tất định + LLM bị ràng buộc.

2026-05-22 · FPT Japan AI Hackathon 2026 · phiên bản MVP 1 ngày

Nguyên lý kiến trúc: Python tất định tính mọi con số; LLM chỉ viết câu chữ. Dữ liệu 5 nguồn được gom, đối soát chéo, mọi fact gắn nguồn (citation), rồi LLM diễn đạt thành báo cáo — và một bộ validator chặn mọi số/mã bịa trước khi xuất.

1. Sơ đồ kiến trúc

Ô vuông = thành phần xử lý · ô thoi = cổng kiểm tra · ô bo tròn = kết quả.

2. Bốn tầng kiến trúc

TầngThành phần (file)Nhiệm vụ
1 · Data insighthub_mcp/, datasource.py Gom 5 nguồn → một ProjectState chuẩn hoá, mỗi bản ghi gắn source_ref.
2 · Reconcile reconcile.py, anomalies.py Đối soát chéo: map Jira↔WBS, tính tiến độ, chạy 15 rule phát hiện bất thường.
3 · Reporting facts.py, report.py, validate.py Tính sẵn mọi fact + citation → LLM viết narrative → validator chặn số bịa.
4 · Output templating.py, export.py Đổ narrative vào template DOCX, xuất .docx / .md / traceability.json.

3. Thiết kế chống "bịa số" (lõi kiến trúc)

Cuộc thi loại thẳng bài có số liệu / ticket không tồn tại. Đây là ràng buộc kiến trúc số 1 — quyết định cách toàn bộ tầng 3 được thiết kế.
1

Python tính, LLM không tính

Mọi con số (tiến độ %, số bug, velocity…) do code Python tất định tính. LLM không bao giờ thấy dữ liệu thô và không tự cộng trừ.

2

Facts có sẵn nguồn

facts.py xuất một object Facts: mỗi con số đi kèm citation trỏ về Jira key / commit / tin nhắn / dòng biên bản.

3

LLM chỉ diễn đạt

report.py đưa LLM chỉ object Facts. LLM viết câu chữ quanh các giá trị có sẵn — không được sinh số mới.

4

Validator chặn cửa

validate.py trích mọi số & mã ID trong bài viết → bắt buộc nằm trong "danh sách cho phép" của Facts. Sai → chặn xuất, bắt LLM viết lại.

4. Tầng MCP — kết nối hệ thống ngoài

Ba hệ thống ngoài (Jira, Chat, GitHub) được bọc sau một MCP server duy nhất — insighthub-mcp với 3 tool:

  • list_jira_issues · list_chat_messages · list_code_activity
  • Adapter 2 tầng: FileAdapter (đọc file export — dùng cho MVP) và ApiAdapter (chỗ trống, sau cắm API thật). Đổi nguồn không đụng pipeline.
  • connections.yaml khai báo "đã kết nối" + tham chiếu biến môi trường cho credential — không lưu secret trong mã.
  • Pipeline gọi MCP qua in-memory client → đúng giao thức nhưng không cần tiến trình phụ → demo ổn định.

WBS Excel và biên bản họp là file upload theo bản chất (không có API) nên nạp trực tiếp, không qua MCP.

5. Luồng chạy một báo cáo

Mục tiêu hiệu năng: báo cáo tuần < 60 giây.

7. Hợp đồng dữ liệu

Mọi tầng giao tiếp qua kiểu dữ liệu cố định trong schema.py (pydantic) — "đóng băng" từ đầu để các phần code song song không lệch nhau:

  • ProjectState — toàn bộ dữ liệu thô đã chuẩn hoá (tầng 1 → 2).
  • ReconcileResult + Anomaly — kết quả đối soát (tầng 2 → 3).
  • Facts — số liệu tính sẵn + citation + danh sách giá trị cho phép (tầng 3 → LLM).
  • Report — narrative 9 mục (tầng 3 → 4).
  • SourceRef — con trỏ truy vết gắn vào mọi bản ghi.
Tóm tắt: kiến trúc là một dây chuyền tất định với LLM được "nhốt" ở đúng một mắt xích (viết câu chữ) và được bao bởi 2 lớp bảo vệ: facts có nguồn ở đầu vào, validator chặn bịa ở đầu ra.
