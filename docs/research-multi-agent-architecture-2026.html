Phát hiện quyết định: Agent SDK & claude -p giờ chạy được trên subscription

Đây là yếu tố làm đảo chiều phần lớn quyết định kiến trúc, vừa có hiệu lực gần như đúng thời điểm này:

Từ 15/06/2026 (2 ngày nữa), các gói subscription Pro, Max, Team, Enterprise nhận một khoản credit Agent SDK hàng tháng riêng biệt, bao phủ: (1) usage của Claude Agent SDK, (2) lệnh claude -p (headless), và (3) third-party apps build trên Agent SDK. Khoản này tách khỏi usage limit tương tác — tức chạy automation/scheduled job không còn "ăn" vào quota chat của bạn nữa.

Xác thực qua OAuth token (prefix sk-ant-oat01-) gắn với tài khoản Claude.ai có subscription, không cần API key trả-theo-token.

Caveat cần biết: Tài liệu SDK vẫn ghi "Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products" — quy định này nhắm vào việc bán/phân phối app dùng login claude.ai cho người dùng KHÁC. Tiêu chí đánh giá

1. Chạy trên subscription

Không bắt buộc API key trả-theo-token. Trọng số cao nhất với bạn.

2. Overhead cá nhân

Không enterprise bloat, không phải nuôi infra (vector DB, message queue, consensus protocol).

3. Compose skill

Thêm/sửa một skill không phá vỡ phần còn lại.

4. Memory / state

Lưu trạng thái bền vững, resume được.

5. Scheduling

Hợp với Windows Task Scheduler + headless.

6. Maturity & maintenance

Được duy trì, không demo-ware, learning curve hợp lý.

4 primitive native bạn sẽ dùng (và khi nào dùng cái nào)

Skills knowledge

.claude/skills/<name>/SKILL.md. Progressive disclosure — Claude chỉ nạp khi cần. Auto-invoke hoặc gọi /name.

Dùng khi: đóng gói "cách làm một việc lặp lại" (collector logic, synthesis prompt, wiki lint rule).

Subagents isolation

.claude/agents/*.md. Mỗi cái có context window + model + tool riêng. Mới (v2.1.172, 9/6/2026): nest được tới 5 cấp, chạy song song; /batch để fan-out.

Dùng khi: cần cách ly context hoặc làm song song (research fan-out, review không làm bẩn context chính).

Hooks enforcement

PreToolUse, PostToolUse, SessionStart, SessionEnd… Chạy ngầm, deterministic.

Dùng khi: ép luật (chặn sửa raw/, auto-load ai/status.md đầu session, audit log mọi tool call).

MCP action

Kết nối hệ ngoài: DB, browser, Telegram, filesystem. Plugins bó gọn skills+agents+hooks+MCP.

Dùng khi: agent cần thực thi ra ngoài (gửi Telegram, query SQLite, đọc Obsidian vault).

Quy tắc nhớ nhanh: Skills = biết cách làm · MCP = làm được ra ngoài · Hooks = ép tuân thủ · Subagents = cách ly & song song.

Kiến trúc khuyến nghị cho ai-project-opus

Mô hình orchestrator-worker (đúng pattern Anthropic dùng cho hệ research multi-agent của họ), ánh xạ trực tiếp lên cấu trúc bạn đang có:

Về memory: Ở quy mô một người, đừng vội kéo mem0 / Letta / vector DB vào. Markdown-as-memory (bạn đã có Obsidian vault + ai/status.md + handoff files) + SQLite cho log là pattern được khuyên dùng cho single-user — đơn giản, grep được, git được, không phải nuôi index. Chỉ lên vector DB khi search ngữ nghĩa trên kho wiki lớn thực sự thành nút cổ chai.

Lộ trình áp dụng (tăng dần, không big-bang)

  • Bước 0 — Giữ nguyên

    Pipeline hiện chạy ổn. KHÔNG refactor toàn bộ. Mọi thay đổi phải surgical, theo đúng Karpathy principles trong CLAUDE.md.

  • Bước 1 — Chuẩn hoá Skills

    Viết SKILL.md cho 3 pipeline cốt lõi (collector, synthesizer, wiki curator). Mỗi skill mô tả input/output/verify. Đây là bước rẻ nhất, giá trị tức thì, không đổi runtime.

  • Bước 2 — Hooks cho rule

    Thêm 1–2 hook: chặn ghi raw/ (PreToolUse), auto-load ai/status.md (SessionStart). Biến luật mềm thành ràng buộc cứng.

  • Bước 3 — Pilot Agent SDK

    Chọn MỘT pipeline ít rủi ro (vd weekly synthesizer). Viết orchestrator bằng Agent SDK Python thay cho claude_cli(). Đo: có ổn định hơn không, error handling/sessions có sạch hơn không. Chờ sau 15/6 để dùng credit subscription.

  • Bước 4 — MCP hoá I/O

    Bọc Telegram + SQLite thành MCP server. Tái dùng across pipelines thay vì code riêng mỗi chỗ.

  • Bước 5 — Dọn legacy

    Sau khi pilot chứng minh được, quyết định gỡ hẳn CrewAI trong crews/ (đã ngoài pipeline chính). Đây là việc bạn đã ghi trong "Next step" của status.md.

SDD gate: CLAUDE.md bắt buộc RD trước khi code feature mới. Báo cáo này là input cho RD, chưa phải lệnh code. Bước 3 (pilot Agent SDK) là feature >20 dòng → cần RD → SD → BD được approve trước khi implement. Coding giao Codex theo routing table; main session (Opus) viết spec/review.

Kết luận một dòng

Bạn không cần thêm framework — bạn cần formalize cái đã có thành Skills + Subagents + Hooks + MCP native, và nâng gateway từ claude_cli() thủ công lên Claude Agent SDK, tận dụng credit subscription mới (15/6/2026). Repo ngoài (claude-flow, MetaGPT, LangGraph…) đều hoặc là overkill cho một người, hoặc buộc API key trả phí — trái với ràng buộc của bạn.
