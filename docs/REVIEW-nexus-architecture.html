Solution Architecture review: điểm mạnh, rủi ro, và khuyến nghị theo mức ưu tiên P0–P3.

2026-06-10 · Reviewer: Claude (vai SA) · Scope: dashboard.html, data layer, nexus-commands pipeline, CI

1. Executive Summary

Nexus là một kiến trúc serverless cá nhân hiếm khi được làm đúng đến vậy: JSON-on-GitHub làm database + audit trail, GitHub Actions làm trusted executor, static SPA làm view, LLM làm input layer. Với quy mô 1 user, chi phí vận hành bằng 0 và độ phức tạp được kiểm soát tốt nhờ non-goals rõ ràng (không backend, không React).

Phát hiện nghiêm trọng nhất (P0): lỗ hổng stored XSS → đánh cắp PAT. Hai render path không escape dữ liệu (dashboard.html:2429 tên món ăn, :3055 mô tả giao dịch). Dữ liệu này do LLM ghi từ ảnh hóa đơn / text chat (= untrusted input), trong khi PAT nằm trong localStorage — script chèn qua một "tên cửa hàng" độc hại có thể đọc PAT và chiếm quyền repo. Fix nhỏ (~10 dòng) nhưng phải làm ngay.

2. Điểm mạnh cần giữ nguyên

✅ JSON-on-GitHub

Version control = audit trail + backup + rollback miễn phí. Đúng quy mô bài toán — một database thật sự sẽ là overengineering ở đây.

✅ Control gate pattern

Paste flow: validate → preview → approve từng item trước khi ghi Calendar. Human-in-the-loop đúng chỗ, events có tag source='opus-nexus' để truy vết.

✅ Secrets hygiene

OAuth refresh token chỉ nằm trong GitHub Secrets; access token Google chỉ in-memory, không bao giờ persist. Làm đúng chuẩn.

✅ Non-goals kỷ luật

"No backend, no React, no notification system" — chống scope creep hiệu quả. Review này không đề xuất phá bỏ các non-goals đó.

3. Findings — theo mức ưu tiên

🔴 P0 — Security (làm ngay, effort S)

#FindingBằng chứngKhuyến nghị
F1 Stored XSS → PAT exfiltration. Hàm esc() có sẵn và được dùng đúng ở proposal/calendar/tasks, nhưng bị bỏ sót ở Vita render: tên macro/món ăn và mô tả giao dịch render thẳng vào innerHTML. Attack path: ảnh hóa đơn / text chat → LLM ghi JSON → dashboard render → script chạy → đọc localStorage.ov_pat. dashboard.html:2429 ${m.name}
dashboard.html:3055 ${t.description||c.lbl}		 (1) Bọc esc() cho 2 vị trí + audit toàn bộ template literal còn lại; (2) thêm <meta http-equiv="Content-Security-Policy"> chặn inline-script ngoài whitelist làm defense-in-depth.
F2 PAT blast radius. PAT trong localStorage là chấp nhận được cho app cá nhân, với điều kiện scope tối thiểu. Nếu đang dùng classic token full-repo thì F1 trở thành chiếm toàn bộ tài khoản. dashboard.html:702 Dùng fine-grained PAT: chỉ repo này, chỉ Contents: Read, có expiry. Dashboard chỉ đọc — không cần quyền ghi.

🟠 P1 — Data integrity: thống nhất write path (effort M)

F3 — Ba write path, ba mức validation. Đây là vấn đề kiến trúc lớn nhất:

Path (a) là nơi mọi lỗi dữ liệu đã xảy ra (dual-key schema, VND/JPY mismatch, nguy cơ quên update index). LLM vừa là người nhập liệu vừa là người giữ toàn vẹn dữ liệu — sai vai.

Khuyến nghị F3: Mọi write đi qua một choke point — mở rộng pipeline nexus-commands thêm add_transaction / add_health_log / add_workout (đã nằm trong RD finance F1.1). Tối thiểu nếu chưa làm ngay: thêm workflow validate-on-push chạy JSON Schema check trên mọi thay đổi *-data/*.json, và index.json do Actions tự rebuild — index là derived data, không bao giờ nên để LLM tự maintain.

F4 — Schema contract ngầm. Schema được định nghĩa 2 lần độc lập: trong prompt (instructions.md) và trong parser (dashboard.html) — đã drift thực tế. Khuyến nghị: đặt schemas/*.schema.json trong repo làm single source of truth; instructions.md, validator pipeline, và dashboard cùng tham chiếu; thêm field schema_version vào mỗi file data để migrate an toàn về sau.

🟡 P2 — Reliability & Performance (effort S–M)

#FindingKhuyến nghị
F5 N+1 fetch, không cache. loadModule() gọi 1 + N request/module (dashboard.html:752-758); range 90 ngày ≈ ~270 API calls mỗi lần mở app. Parallel (Promise.all) nên không chết, nhưng chậm trên mobile và phí rate limit. Actions build file rollup tháng YYYY-MM.json (3 calls thay vì 90), hoặc cache localStorage theo SHA của index. Range 7–14 ngày hiện tại: chưa cần vội.
F6 Pipeline fail im lặng. Lệnh nexus-command lỗi (token hết hạn, validate fail) → file không được archive, user không biết — tưởng lịch đã được tạo. Đây là silent data loss ở UX level. Workflow failure → move file vào nexus-commands/failed/ + tạo GitHub Issue (hoặc 1 file status.json dashboard đọc được để hiện badge ⚠).
F7 Executor không có test. exec-command.js chạy tự động với quyền ghi Calendar/Tasks nhưng 0 test — sửa validation là dò mìn. Vài unit test bằng node --test (zero dependency, giữ đúng triết lý) cho phần validate; chạy trong workflow trước bước execute.

⚪ P3 — Maintainability & Evolution (làm khi chạm ngưỡng)

#FindingKhuyến nghị
F8 Single file 3.3k dòng — vẫn ổn nhờ section convention (// ══ TAB 3 ══), nhưng mỗi feature mới (RD finance F2, Pecunia) cộng thêm vài trăm dòng. Khi vượt ~5k dòng: build-concat tối giản — tách src/*.js, CI ghép thành dashboard.html. Vẫn single-file khi deploy, vẫn không framework. Không migrate React.
F9 Hướng evolution: lớp agent skills (Pecunia) đặt cạnh kiến trúc hiện tại là đúng — không đụng non-goals, tái dùng pipeline làm execution layer. Giữ nguyên tắc: skills chỉ được ghi qua pipeline (F3), không ghi file trực tiếp — như vậy choke point validation phục vụ luôn cả agent layer.

4. Kiến trúc đích đề xuất (không phá non-goals)

Thay đổi cốt lõi so với hiện tại chỉ là một câu: "dashboard chỉ đọc, mọi ghi đi qua pipeline". Mọi thứ khác (single-file SPA, JSON-on-GitHub, paste flow approve) giữ nguyên.

5. Thứ tự thực hiện đề xuất

  • Tuần này

    P0: esc() 2 vị trí + audit render + CSP meta + đổi fine-grained PAT read-only. (~nửa ngày, độc lập với RD finance)

  • Cùng RD finance F1

    P1: mở rộng pipeline (add_transaction…), JSON Schema trong schemas/, Actions rebuild index. (gộp chung BD với RD finance để khỏi làm 2 lần)

  • Sau 1 tháng data

    P2: rollup tháng + failed/ + status badge + unit test executor.

  • Khi chạm ngưỡng

    P3: build-concat khi dashboard vượt ~5k dòng.

6. Những gì cố tình KHÔNG khuyến nghị

❌ Backend / database thật — quy mô 1 user không justify chi phí vận hành; git đang làm tốt vai trò này.

❌ React / framework migration — 3.3k dòng vanilla có section convention vẫn rẻ hơn một build toolchain.

❌ Real-time sync / push notification — đúng như non-goals hiện tại; mở app là đủ với usage pattern này.

❌ OAuth proxy server cho PAT — đúng về lý thuyết bảo mật nhưng phá nguyên tắc no-backend; fine-grained read-only PAT + fix XSS là đủ cho threat model cá nhân.
