Quality Gate Definitions

Every merge to main must pass these gates. Gates run automatically via CI.

Gate 1 — Lint & Format

Scope: All Python + TypeScript files

  • ruff check — no errors, no warnings
  • ruff format --check — formatting consistent
  • tsc --noEmit — no type errors
  • Commit messages follow Conventional Commits

Target: <15s · Runs on every push

Gate 2 — Test Suite

Scope: harness/hub/tests/

  • pytest harness/hub/tests/ — all pass
  • Min coverage: 80% on changed files
  • No flaky tests (3 consecutive passes required)
  • Existing tests must not break

Target: <2min · Runs on PR + push to main

Gate 3 — Security Scan

Scope: Dependencies + secrets

  • pip-audit — no known vulnerabilities
  • gitleaks — no secrets in code
  • No sensitive data committed (finance, health)
  • Dependency review on PR

Target: <1min · Runs on PR

Management Rules — CI/CD & Workspace Governance

Quy tắc quản lý workspace, branch, merge, deploy. Áp dụng cho tất cả project trong ai-project-opus.

2. Merge Rules

RuleSeverityAutoDescription
No direct push to main Critical ✓ Branch protection Merge only through PR or git merge --no-ff with descriptive message. Main branch protected on GitHub.
All quality gates must pass Critical ✓ CI check Gate 1 (Lint) + Gate 2 (Tests) + Gate 3 (Security) must all pass before merge.
No sensitive data in commits Critical ✓ gitleaks Finance DB, health data, user profiles — never commit. Use .gitignore and .env.
Resolve conflicts before merge Critical ✓ Git enforces AI auto-resolves obvious conflicts; escalates only when both sides change same content.
Fetch + merge before push High ✓ AI workflow Before any push: git fetch origin → git merge origin/main → push. Remote often ahead (autosync).
Delete merged branches High — Manual After merge, delete local + remote branch. Clean up worktrees.
Use --no-ff for feature merges Medium — Convention Preserves feature history. Merge commit message lists all included changes.
Conventional Commits Medium ✓ gitlint type(scope): description — type: feat|fix|perf|refactor|docs|test|chore

3. Branch Lifecycle

Branch lifecycle — create → develop → review → CI → merge → cleanup

4. Branch Age Policy

AgeSeverityActionDescription
< 3 days Low Normal Active development — no action needed
3–7 days Medium Warning Dashboard shows yellow dot. Nightly report flags it.
7–14 days High Review required Must be merged, archived, or given extension with reason.
> 14 days Critical Auto-delete candidate Marked for deletion. Nightly job warns, then deletes after 21 days.

5. Deployment Rules

RuleSeverityDescription
Deploy only from main Critical All deployments originate from main branch. No direct deploys from feature branches.
Harness deploy on merge High When harness/** changes merge to main, trigger harness deployment pipeline.
Dashboard sync on change High health-app/dashboard.html changes auto-sync to opus-vita (GitHub Pages). Already implemented.
No deploy during business hours (optional) Low Non-urgent deploys batched to off-hours. Hotfixes exempt.
Rollback within 15 min High If deploy fails health check, auto-rollback to previous commit.

6. Data Safety Rules

⛔ Cấm commit/push dữ liệu nhạy cảm:

Critical Finance DB opus-animus/opus-actio/finance.db, data/_local/ Never commit real financial data. Use .gitignore. No real numbers in pushed docs.
Critical Health data health-data/, personal logs Personal health metrics never committed. Already in .gitignore.
High User profile user-profile/ Personal profile data excluded from commits.
High API keys / tokens .env, secrets Use .env (gitignored). GitHub Secrets for CI. Never hardcode.

7. Worktree Management

RuleSeverityDescription
Max 3 active worktrees Medium Limit concurrent worktrees to avoid context fragmentation. Clean up after merge.
Worktree follows branch Medium When branch is deleted, its worktree must be removed too. No orphaned worktrees.
Name worktrees descriptively Low Use branch name or task slug. No generic names like "tmp".

8. Nightly Health Check (Proposed)

Planned: Scheduled workflow runs daily at 02:00 UTC. Checks:
  • Stale branches — flag branches >7 days without activity
  • Orphaned worktrees — detect worktrees pointing to deleted branches
  • Test flakiness — run full test suite 3×, flag inconsistent results
  • Dependency audit — pip-audit + npm audit for all projects
  • Disk usage — warn if workspace exceeds 5GB
  • Generate report — update this dashboard with fresh data
