1. Vision

Các app tài chính truyền thống (Moneytree, Zaim, MoneyForward) chỉ làm được một nửa: ghi nhận quá khứ. Chúng không hiểu kế hoạch 5 năm của bạn, không biết bạn đang cân nhắc ở lại Nhật hay về Việt Nam, và không tự đặt câu hỏi "tháng này có gì bất thường?".

Core promise: Pecunia không phải app để bạn nhập liệu. Pecunia là một cố vấn tài chính agent — bạn nói chuyện, gửi ảnh hóa đơn, đặt câu hỏi; agent ghi sổ, đối chiếu kế hoạch, cảnh báo lệch hướng, và mỗi tháng tự ngồi xuống review với bạn như một CFP planner thực thụ.

Tagline: "Log bằng một câu chat. Plan bằng một cuộc hội thoại."

2. Tại sao Agent Skills thay vì app truyền thống?

App truyền thống (build UI)

✗ Phải build + maintain UI nhập liệu, backend, auth

✗ Nhập liệu thủ công → bỏ cuộc sau 2 tuần

✗ Logic tư vấn cứng, không hiểu ngữ cảnh đời sống

✗ Thêm tính năng = thêm code

Agent Skills (concept này)

✓ Input = chat tự nhiên + ảnh hóa đơn (zero UI)

✓ Mỗi skill = 1 file SKILL.md — sửa hành vi bằng văn bản

✓ LLM hiểu ngữ cảnh: "tháng này về VN nên transport cao"

✓ Tái dùng toàn bộ hạ tầng Nexus đã chạy: JSON-on-GitHub, Actions pipeline, dashboard

Nguyên tắc kế thừa từ Nexus: chat-first, không build UI nhập liệu, static dashboard chỉ để xem, dữ liệu là JSON trên GitHub (version control = audit trail miễn phí).

4. Bộ Skill — trái tim của app

Mỗi skill là một folder .claude/skills/<tên>/SKILL.md với vai trò, trigger và guardrails riêng:

📒 /fin-log — Kế toán viên

Trigger: "ăn trưa 850", ảnh hóa đơn, "lương về".

Parse JPY-first (円/¥/万), auto-categorize, gắn payment_method + bucket, commit lệnh add_transaction → Actions merge vào finance-data/.

Guardrail: income tự làm tròn theo privacy policy trước khi lên GitHub.

MVP — Phase 1

📊 /fin-review — Cố vấn tháng

Trigger: "/fin-review" cuối tháng, hoặc Actions tự nhắc ngày 1.

Đọc toàn bộ transactions tháng + recurring + goals → diagnosis traffic-light (cashflow / emergency fund / debt / NISA) → draft snapshots/YYYY-MM.md đã sanitize + 3 action items. User duyệt rồi mới commit.

MVP — Phase 2

🧭 /fin-plan — Kiến trúc sư dài hạn

Trigger: "/fin-plan", hoặc khi có quyết định lớn (đổi việc, mua nhà, về VN).

Làm việc trên personal-finance/: goal buckets, emergency fund target, lộ trình NISA/iDeCo, mô phỏng kịch bản Ở-Nhật vs Về-VN, cập nhật 12-month roadmap. Ghi mỗi quyết định vào decisions/ (decision log).

Phase 3

💬 /fin-advisor — Hỏi đáp có kỷ luật

Trigger: câu hỏi bất kỳ: "tháng này tiêu được bao nhiêu nữa?", "nên max NISA không?"

Trả lời dựa trên data + plan thật, không chung chung. Tôn trọng gate: chưa đủ quỹ khẩn cấp 3 tháng → không nudge đầu tư.

Guardrail: không khuyên mua sản phẩm cụ thể — chỉ đưa framework + tiêu chí.

Phase 3
Ví dụ cấu trúc 1 skill — /fin-log 
.claude/skills/fin-log/
├── SKILL.md          # vai trò, trigger, parse rules JPY, category map,
│                     # privacy guard, output format
├── schema.json       # transaction schema v2 (payment_method, bucket)
└── examples.md       # 10 ví dụ input → JSON chuẩn (few-shot)

Sửa hành vi app = sửa SKILL.md. Không deploy, không build. Đây chính là điểm khác biệt của "app bằng agent skills".

Privacy là tính năng, không phải ghi chú: mọi skill đều có bước sanitize-before-commit bắt buộc (kế thừa FINANCE_DATA_STORAGE_POLICY 2-layer: số chính xác ở local/chat, GitHub chỉ giữ range + derived metrics).

6. Vòng đời một tháng (agent flywheel)

Vòng lặp Log → Aggregate → Review → Decide → Adjust chính là điểm "app truyền thống không làm được": dữ liệu chảy ngược lên kế hoạch, kế hoạch chảy xuống hành vi chi tiêu hằng ngày (safe-to-spend, gate đầu tư).
