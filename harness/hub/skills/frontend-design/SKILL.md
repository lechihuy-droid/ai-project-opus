# Frontend Design

Use this skill to create or critique an interface direction.

1. Name the user, decision, primary task, content density, and operating context.
2. Establish one visual hierarchy and one recognizable design idea instead of uniform cards and generic decoration.
3. Choose typography, spacing, color, and chart forms for meaning, not novelty.
4. Design loading, empty, stale, error, permission, and success states alongside the happy path.
5. Check responsive layout, keyboard use, focus visibility, contrast, motion reduction, and readable data density.
6. Tie critique to observable UI evidence and propose prioritized changes.

Return a design contract or findings; do not claim pixel accuracy without a rendered artifact or screenshot evidence.
