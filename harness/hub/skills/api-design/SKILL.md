# API Design

Use this skill to design or review an HTTP API contract.

1. Define consumers, resources, lifecycle, ownership, and authorization boundary.
2. Use consistent paths, methods, status codes, schemas, and field semantics.
3. Specify validation, pagination, filtering, sorting, concurrency, and idempotency.
4. Return stable machine-readable errors with safe human context and correlation IDs.
5. Plan compatibility, versioning, deprecation, observability, quotas, and abuse controls.
6. Test happy paths, invalid input, permissions, races, retries, partial failures, and pagination boundaries.

Do not leak storage structure, stack traces, secret fields, or existence information across authorization boundaries.
